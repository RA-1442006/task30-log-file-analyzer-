# Log File Analyzer (Task 30)

A lightweight, pure Python command-line utility built to parse web server access logs (Apache/Nginx format) and generate clear analytical summary reports.

---

## Objective

The goal of this project is to build an automated log analyzer that reads server access logs line by line, safely handles corrupted or malformed entries, and produces actionable insights including:
- Total request volume
- Error response frequency (4xx client and 5xx server errors) with a status code breakdown
- Top 5 most active IP addresses
- Top 5 most requested endpoints
- Count of skipped malformed lines

---

## Tools Used

- **Language:** Python 3 (standard library only)
- **Built-in Modules:**
  - `collections.Counter`: for frequency counting and ranking top occurrences
  - `re`: for regular expression pattern matching on log entries
  - `csv`: for exporting structured tabular data
  - `sys`: for command-line argument processing

No third-party packages or external dependencies are required.

---

## How to Run

Clone or download the project folder, open your terminal inside the folder, and run:

```bash
# Run with the default sample log file (sample_access.log)
python log_analyzer.py

# Or pass a custom log file as an argument
python log_analyzer.py path/to/your/server.log
```

When executed, the script prints the analysis to your terminal, saves a text summary in `report_output.txt`, and exports a CSV breakdown in `report_summary.csv`.

## Log Format Explanation

The script parses standard Apache/Nginx **Common Log Format (CLF)** and **Combined Log Format** entries. 

Here is an example log line:
```text
192.168.1.10 - - [28/Oct/2026:10:02:54 +0000] "GET /products HTTP/1.1" 200 4520
```

### Extracted Fields:
1. **IP Address (`192.168.1.10`):** The client's IP address that made the request. Used to track traffic sources and identify frequent visitors or potential rate-limit abusers.
2. **Timestamp (`[28/Oct/2026:10:02:54 +0000]`):** The date and time the request was received by the server.
3. **HTTP Method (`GET`):** The request method (e.g., `GET`, `POST`, `PUT`, `DELETE`).
4. **Endpoint (`/products`):** The resource or URL path requested by the client.
5. **Status Code (`200`):** The 3-digit HTTP response code returned by the server (e.g., 200 OK, 301 Redirect, 404 Not Found, 500 Internal Error).
6. **Response Size (`4520`):** The size of the response returned to the client in bytes.

## Approach: Separation of Parsing and Analysis

To keep the code clean and maintainable, the program separates data ingestion and parsing from business logic and reporting:

1. **`parse_line(line)`**: Focuses purely on string parsing. It uses a regular expression to test if a line matches the log format. If valid, it extracts and returns a clean dictionary; if malformed, it returns `None`.
2. **`read_log_file(filepath)`**: Handles file I/O line by line. It catches file errors (`FileNotFoundError`, empty files) gracefully and counts skipped malformed lines without crashing.
3. **`analyze_logs(parsed_logs, skipped_count)`**: Takes the parsed data and computes statistics using `Counter`. It has no dependency on how files are opened or printed.
4. **`print_report(analysis)` & `save_report(report_text)`**: Handle presentation and output formatting.
5. **`export_csv_summary(analysis)`**: Handles structured data export using the `csv` module.
6. **`main()`**: Acts as the orchestrator to tie the flow together.

## Interview Questions & Answers

### 1. Why are logs useful?
Logs provide an immutable chronological record of server events, user interactions, and system errors. They are essential for debugging issues in production, monitoring application performance, auditing security events, and understanding user traffic patterns.

### 2. How would you identify the most frequent IP address?
You extract the IP address from each valid log record and increment its count in a dictionary or `collections.Counter`. After tallying the requests, you can retrieve the highest count using `Counter.most_common(1)` or Python's `max(ip_dict, key=ip_dict.get)`.

### 3. What is collections.Counter?
`collections.Counter` is a dictionary subclass from the Python standard library designed specifically for counting hashable elements. It stores items as keys and their counts as values, returns `0` instead of raising a `KeyError` for missing keys, and provides handy helper methods like `most_common()`.

### 4. How would you process a very large log file?
Instead of loading the entire file into memory with `readlines()`, you read it line by line using an iterator (`for line in file:`). You update counters or aggregate metrics on the fly during a single pass, which ensures that memory usage stays constant regardless of whether the log file is 100 MB or 100 GB.
